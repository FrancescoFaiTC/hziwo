# 红中麻将计分器（hziwo）

**版本 1.0.0** · MIT License

面向手机和平板的红中麻将多人计分 Web 应用。支持本轮加减分、抽水池、比赛历史，以及结算阶段的分池与积分倍化。数据保存在浏览器本地，刷新页面不会丢失。

## 功能概览

| 模块 | 说明 |
|------|------|
| **计分** | 为本轮填写玩家与抽水池的积分变动，零和校验后确认结算 |
| **牌桌** | 新增玩家、切换在座 / 候补；在座最多 4 人 |
| **结算** | 自动或手动分配抽水池，再按倍数做积分倍化；支持回滚 |
| **积分台** | 展示在座与候补玩家当前总分（带正负号） |
| **比赛历史** | 查看各轮变动；删除记录不会改动当前积分 |
| **本地存储** | 使用 `localStorage`，无需账号与后端 |

## 使用说明

### 1. 牌桌：加人与座位

1. 打开底部 **牌桌**。
2. 填写名字与初始积分，点 **新增**。
3. 在座名额未满时，新人默认 **在座**；满 4 人后默认 **候补**。
4. 可用行内按钮在「在座 / 候补」之间切换（在座上限 4 人）。

### 2. 计分：记录本轮

1. 打开底部 **计分**。
2. 为抽水池与各玩家填写本轮加减分（可为负）。
3. **合计必须为 +0**（玩家变动 + 抽水池变动之和为零）。
4. 抽水池结算后余额不能为负（可以为 +0）。
5. 可选：打开「记录比赛历史」。
6. 点 **结算本轮** → 核对确认框 → **确认结算**。
7. 如需撤销刚入账的一轮，可用 **撤销上一轮**（不会删掉之后新加的玩家）。

### 3. 结算：分抽水池与倍化

1. 打开底部 **结算** → **进入结算**（计分会暂停，可随时 **继续比赛**）。
2. **分抽水池**
   - **自动分抽水池**：只分给在座玩家；先均分，余数优先补给当前分较低者。
   - **手动分抽水池**：给每人填非负整数，合计须等于池内余额。
   - 执行前都会弹出积分变动确认；可用 **回滚操作** 撤销最近一次分池。
3. **积分倍化**
   - 要求抽水池为 **+0**。
   - 设定正整数倍数后确认；确认框会展示倍率与每人前后积分。
   - 可用 **回滚操作** 撤销倍化。
4. 分池或倍化成功后，「撤销上一轮」不可再跨过结算改动（避免冲掉已结算分数）。
5. **重新开始** 会清空玩家、历史、抽水池与结算状态，且不可恢复。

### 4. 数字与符号约定

- 与积分相关的展示：`0` 与正数带 `+`，负数带 `-`（例如 `+12`、`-3`）。
- 积分**倍数**本身不带 `+`（例如 `2`）。
- 手机上数字键盘往往没有负号：可用步进器左侧 **−** 调成负数；桌面可直接输入。

## 环境要求

- **Node.js** ≥ 20（建议使用当前 LTS）
- 包管理器：`npm`（也可用 pnpm / yarn，按习惯调整命令即可）

## 快速开始

```bash
# 克隆仓库后进入目录
cd hziwo

# 安装依赖
npm install

# 启动开发服务器
npm run dev
```

浏览器访问 [http://localhost:3000](http://localhost:3000)。

可选：复制环境变量示例（当前业务不依赖服务端密钥）：

```bash
cp .env.example .env.local
```

## 项目结构

```text

│   ├── app/                      # Next.js App Router（布局、首页、样式）

│       ├── game/                 # 状态机、校验、计算、持久化
│       └── utils.ts
├── public/                       # 静态资源
├── LICENSE
├── README.md
├── package.json
├── .env.example
├── .editorconfig
├── .gitattributes
└── .gitignore
```

核心逻辑在 `src/lib/game/`（回合结算、抽水池分配、倍化与回滚）；界面在 `src/components/mahjong/`。

## 数据与持久化

| 项 | 值 |
|----|-----|
| 存储位置 | 浏览器 `localStorage` |
| 键名 | `hziwo-mahjong-game-v1` |
| 范围 | 玩家、积分、抽水池、比赛历史、结算阶段快照等 |

说明：

- 数据只存在当前浏览器 / 设备，换机或清站点数据会丢失。
- 无服务端同步；适合牌局现场本机使用。
- 加载时会做基本结构校验；无法识别的旧数据会回退到初始状态。

## 部署

可部署到任意支持 Next.js 的平台（例如 [Vercel](https://vercel.com/)）：

1. 将仓库推送到 GitHub。
2. 在 Vercel 导入该仓库，使用默认 Build / Output 设置即可。
3. 构建命令：`npm run build`；输出为 Next.js 标准产物。

静态导出（`output: 'export'`）未默认开启；若需要纯静态托管，需自行评估动态能力后再改配置。
